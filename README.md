# 闻势 MarketPulse —— AI 驱动的 A 股市场大势研判（真实数据版）

> 面向 A 股投研场景的 **AI Native 市场大势研判产品**：基于行情结构、市场宽度、风格轮动、估值、流动性、情绪与事件等**真实数据**，帮助用户理解当前市场状态、主要矛盾及判断可能改变的条件。
> **严格合规：不预测涨跌、不给出买卖/仓位建议、不承诺收益；事实/归纳/推断严格区分；结论全程可追溯；数据异常绝不静默。**

这是一个**可持续运行的全栈服务**：服务端定时抓取真实行情、按交易日自动更新、日频历史序列持续累积。

- **在线地址（可实际操作）**：https://marketpulse-research.app.workbuddy.host/?sharecode=GLUCRWX37H
- 源码目录：`market-pulse/`（本文件即其 README）

## 二、架构

```
server.js               HTTP 服务（API + 静态前端）· 单端口
src/config.js           配置与交易日历（节假日表）
src/pipeline.js          取数编排：8 个数据集并发抓取 + 健康标记 + 缓存回退
src/engine.js            研判引擎：证据 → 信号投票 → 状态/置信度 → 触发条件
src/scheduler.js         调度：交易时段 15 分钟 / 收盘后 10 分钟 / 非交易时段 2 小时
src/store.js             持久化：快照 + 日频历史序列 + 数据集缓存（JSON 落盘）
src/providers/eastmoney.js  真实行情适配器（多节点轮换容灾）
src/providers/fuyao.js       扶摇适配器（配置 Key 后启用）
src/providers/ifind.js       iFinD MCP 适配器（配置后启用）
public/index.html        前端（原生 JS，无构建依赖）
data/                    快照、历史序列、数据集缓存
```

## 三、产品选择（关键设计决策）

1. **四层证据框架**：事实（数据源原始读数）→ 归纳（明示规则的统计结论）→ 状态研判（11 项信号投票 + 置信度）→ 触发条件（可证伪的状态切换条件）。从产品结构上保证"事实、归纳与不确定判断必须区分"。
2. **研判 = 状态理解，而非涨跌预测**：输出"当前处于什么状态 + 主要矛盾 + 什么情况下判断会被推翻"，从机制上杜绝涨跌预测与仓位建议。置信度定义为**证据一致度**（支持 vs 制约信号比例），而非上涨概率。
3. **规则驱动引擎而非黑箱模型**：每个结论可回溯到具体证据编号与信号读数；数据不可用时强制下调置信度并显式计数。这是有意为之的合规设计（可解释 > 不可解释）。
4. **数据健康一等公民**：独立数据健康页 + 故障注入演练；任何缺失/过期/失败都会显式告警，绝不静默生成"正常"结论。
5. **真实数据优先 + 多源容灾**：无官方凭证时也要跑真实数据，故选择免 Key 的公开行情接口为主源，并准备腾讯/新浪备用源与东财多节点轮换；官方源（扶摇/iFinD）配置后自动优先。
6. **新闻只做归档与规则标注，不做情绪解读**：分类/重要度/热度均为规则统计并标注为"归纳"，不生成新闻驱动的买卖倾向。
7. **零第三方依赖**：Node 内置模块 + 原生前端，便于长期运行与审计，降低供应链与维护成本。

## 四、AI 的角色

- **开发过程中的 AI**：WorkBuddy 大模型智能体负责需求拆解、架构设计、全栈代码生成、数据源可行性验证与文档撰写；候选人负责修正错误与合规复核（见 `docs/AI使用与验证记录.md`）。
- **产品内的 AI（研判引擎）**：扮演"策略研究助理"，按固定框架执行 **取数 → 计算 → 归纳 → 输出带置信度的状态研判**：
  - 每次研判先生成取数计划（对象/区间/调用顺序），并在界面"取数计划追溯"中展示；
  - 每条输出必须归类为 事实 / 归纳 / 推断 并带徽标；
  - 输出规范内置禁用词（必涨/必跌、建议买卖、目标点位、收益承诺等）；
  - 数据不可用时输出"该证据不可用"并下调置信度，**绝不编造数据**；
  - 不参与：涨跌预测、个股推荐、仓位建议。

## 六、自动更新机制

- 服务端 scheduler 按**北京时间**判断：交易日盘中每 15 分钟、收盘后 10 分钟一次、非交易日每 2 小时；收盘后自动写入当日快照。
- 每次取数把关键指标（收盘价、成交额、上涨占比、两融、涨停数、估值）写入 `data/history.json`，**日频累积、长期可用**。
- 收盘价与成交额由指数日K**真实回填**（可回溯到每个历史交易日）；宽度/两融等无法回溯的字段如实保留缺口，**不插值、不编造**。
- 取数失败时：优先回退该数据集上一次成功结果并**显式标记为 stale**（界面显示"已回退上次成功值"）；无缓存时证据挂起并下调置信度。

**其他**：Markdown 报告导出（`/api/report`）、页面 60 秒自动刷新、手动立即刷新、数据时点与市场阶段标识、数据源连通性诊断（`/api/diag`）、**前端渲染回归冒烟**（`npm run smoke`，见下）。

**图表实现说明**：全部图表由 `public/index.html` 内的原生 SVG 函数绘制（`radarChart` / `barChart` / `multiLine` / `dualLine` / `heatMatrix` / `donut` / `heatTiles`），**零第三方图表库**，无构建步骤；配色遵循 A 股习惯（红涨绿跌），并在每图下方明确"颜色仅表示方向与大小，不代表好坏评价、不构成涨跌预测"。

## 八、新闻快报设计要点

- **真实抓取 + 每日归档**：每次取数抓 50 条快讯，按新闻日期写入 `data/news/YYYY-MM-DD.json`，累积去重，保留近 30 天；页面可按日期回看。
- **规则自动分类（归纳）**：7 类关键词规则打标，界面明确标注"规则自动标注（归纳）"，可能存在归类偏差，保留"其他"类别不强行归类。
- **重要度**：命中高权重词（央行/证监会/国务院/降准/美联储…）标"重要"，次要标"关注"，其余普通。
- **关键词热度**：预置词表命中次数统计（真实词频，非情感判断）。
- **合规**：新闻仅作事件背景，相关标的标注"事件关联，非推荐"，不做倾向性解读、不生成新闻驱动的买卖建议。

## 九、合规与已知边界

**合规红线（已内建）**
- 不输出确定性涨跌预测、目标点位、收益承诺；不给出买入/卖出/加仓/减仓/清仓建议（文案自动扫描校验）。
- 事实（原始读数）/ 归纳（明示规则统计）/ 推断（含不确定性解释）三类以徽标严格区分。
- 每条结论可追溯至原始字段，标注来源、时点、单位、统计口径。
- 数据缺失/过期/失败时显式告警并挂起证据，绝不静默生成"正常"结论。
- 未提交任何 API Key、用户隐私或受限数据（凭证仅走环境变量与浏览器本地）。

**已知边界**
- 研判引擎为规则驱动（11 项信号投票），非统计预测模型——有意为之的合规设计。
- 新闻分类基于关键词规则，存在归类偏差；保留"其他"类别不强行归类。
- 宽度/两融/涨停等历史序列自系统首次运行起累积，早期缺口如实保留、不插值。
- 备用源（腾讯日K）无成交额字段时，量能证据自动切换为成交量口径并在"口径"字段如实标注。
- 估值分位采用蛋卷口径，与官方口径可能存在差异（已在证据口径中标注）。
- 免费公开接口存在限流风险；生产环境建议配置扶摇 / iFinD 官方凭证。
- 部署沙箱若重启，`data/` 下的日频序列会保留（随源码一起保存），但宽度等无法回溯的字段需重新累积。
- 可视化图表中的**归一化、相关性、分布**均为描述性统计：归一化刻度不代表好坏，相关性只描述历史共同波动、**不构成因果或预测**；雷达图不可用维度按 0 绘制并显式标注，不做估算填补。
- 扶摇适配器的**字段解析**已用官方文档示例做过自测（`npm run test:fuyao`，19 项通过），但**当前部署未配置 API Key**，因此尚未在真实鉴权环境下验证过官方返回（尤其指数 thscode 是否支持指数标的、快讯 `tag_id` 权限）。配置 Key 后请用 `/api/fuyao/diag` 做一次连通性校验；官方源失败时系统自动回退公开源并如实标注。

**未做事项**
- 个股推荐、组合优化、自动交易、用户画像/持仓分析（涉合规且与产品定位无关）。
- 多用户账号体系、权限管理（单用户研究工具定位）。
- 移动端原生适配（当前为响应式网页）。
- 未接入交易所Level-2、北向资金实时等付费数据源。
